# 镜像采集与机器人发布

## 模块边界

```text
source/      源站客户端、Cookie、限流、短期缓存、数据结构与时间解析
collection/  窗口扫描、分页恢复、删除提示处理
planning/    源站文章 → 发帖/回复原子任务
publishing/  HTTP 分发器、机器人发布事务、通知与幂等回执
scheduling/  硬代码版面配置的执行、PostgreSQL 租约、暂停与恢复
ui/          管理员概况、原子任务明细、服务端操作
 dev/        本机配置、模拟源站、只读探针、集成测试
```

采集器不提供外部 API，也不直接写帖子和回复。后台将文章整理为 MirrorAction，通过受密钥保护的机器人发布接口逐条执行。界面的操作使用 Server Actions；现有手动执行路由只作为兼容入口负责入队，不在请求里抓取内容。

## 数据与进度

- MirrorRun：固定的起止时间窗口、下一版面页、当前候选主题、下一帖子页、请求与缓存统计。
- MirrorAction：按 `(boardName, sourcePostId)` 唯一，区分待发布、重试、失败和已发布。
- MirrorBoardState：暂停状态、下一次执行时间、最近完整采集窗口。
- MirrorLease：跨进程互斥，120 秒租约，每 20 秒续期；旧持有者不能释放新持有者的租约。
- MirrorThreadState：一分钟内的重复主题检查缓存；不作为已发布进度。

采集一页时，任务和页码在同一个数据库事务保存。版面时间窗口只用于发现活跃主题。批量读取主题进度，按 `floor((collectedThroughFloor + 1) / 10) + 1` 直接请求缺失页，向后补齐；回复不再按发布时间过滤。每轮调度最多读取 8 页，再让出执行机会。下次继续未完成扫描，不用源站回复总数推测已保存的内容。

源站客户端固定访问 `https://bbs.byr.cn/n/b/`，复用内存 Cookie；默认请求间隔 800 ms、20 秒超时，网络/限流最多 3 次尝试。响应缓存 20 秒、上限 200 个条目，缓存保留原观察时间。会话失效只尝试重新登录一次。未知提示页视为错误，不能把所有 HTML 都当作删帖。

## 发布与通知

内部接口 `POST /api/internal/bots/actions` 只接收已存在的 actionId，并要求专用 BOT_PUBLISH_TOKEN。分发器只允许调用本机回环地址，不接受浏览器传入任意正文或机器人 ID。

发布事务获取主题级 advisory lock，再检查任务回执、机器人权限，创建内容、通知和回执。重复请求以及“已提交但响应丢失”的情况不会重复发帖或通知。失败最多自动尝试 5 次，之后在管理页手动重试。

帖子订阅在新回复发布时生成 thread_reply；明确引用源站回复 ID 时才生成 reply_quote。当前源站样本不保证包含 reid，因此仅有引用作者文字时不猜测被引用楼层，也不宣称所有回复引用都已识别。发布时间早于订阅创建时间的历史内容不补发通知。同一人同时订阅两个目标时，一次发布最多通知一次。

源站楼层不会重新编号。重复楼层直接关联已有回复，不改正文、不生成通知、不记异常日志；非重复回复必须恰为连续发布位置加一，否则拒绝。旧主题首次扫描楼层校准连续进度，后续直接读取状态。历史缺口、采集缺口和发布异常写入 `mirror_anomalies`，保存版面、主题、任务、阶段、原因与时间，供人工复查；异常记录在发布事务回滚后独立提交。源站删除导致的跳楼同样拒绝并记录，不擅自跳过。

## 配置

- `BBS_USERNAME`、`BBS_PASSWORD`：源站账号，仅服务器使用。
- `BOT_PUBLISH_TOKEN`：至少 32 字符的随机发布密钥。
- `BOT_PUBLISH_BASE_URL`：本机回环地址；部署默认 `http://127.0.0.1:3000`。
- `MIRROR_ENABLED=true`：启动新调度器，关闭时仍可查看状态。
- `MIRROR_SOURCE=fixture`：仅限开发；生产环境拒绝模拟源站。
- `LOCAL_DEV_AUTH=true`：仅非生产环境、本机 Host、本机数据库同时满足时有效。

任务定义在 config.ts。IWhisper 每 60 分钟回看 90 分钟；JobInfo 每 30 天回看 31 天。停机后窗口会覆盖上次完整完成时间之前 5 分钟，避免仅按当前时间缩短窗口。

## 本机开发

仓库根目录：

```sh
pnpm install --frozen-lockfile
pnpm dev:setup
pnpm dev:local
```

打开 http://127.0.0.1:3307/admin/scheduled-tasks 或 http://127.0.0.1:3307/me 。开发服务器仅绑定本机，使用独立端口，默认 Webpack，以避开外置卷上的 Turbopack 缓存问题。初始化脚本创建 `.env.local`（权限 600），不覆盖 `.env` 中的真实认证配置，默认模拟源站且不开自动调度。

```sh
pnpm mirror:tick   # 本机执行一轮，包含真实 HTTP 发布到本机服务
pnpm mirror:test   # 单元测试 + 独立数据库 schema 的集成测试
pnpm ui:test      # Playwright 桌面、手机交互与截图
pnpm mirror:probe # 需配置源站账号；仅登录、读一页版面和一页帖子，不入队、不发帖
```

首次运行界面测试先执行 `pnpm --filter @bbs/web exec playwright install chromium`。集成测试强制要求本机数据库，创建随机临时 schema，结束时只清理该测试 schema。真实论坛账号不应写入测试用例。

## 运维与限制

生产部署先执行 `prisma migrate deploy`，本次迁移只增加 5 张新表，不更改历史内容表或全量抓取实现。迁移成功后再启动新服务。新版 instrumentation 不再启动旧定时器；历史全量导入代码保留但不接入此链路。

源站时间是展示文本，不保证秒级精度；分页也不是一致性快照。窗口重叠和源站 ID 去重可降低翻页漂移的影响，但源站在采集前删除的内容无法恢复。正文当前转为安全纯文本，保留换行和文本链接，不下载附件。

已发布任务回执必须保留以保证永久去重；当前版本尚未自动归档正文载荷。管理员页面只读取最近 20 条任务和最近一轮采集，避免读取全部运行历史。
